FLUX.2

FLUX.2 is Black Forest Labs’ second-generation rectified-flow transformer family. It uses a 32-channel VAE and a large language model as its text encoder. InvokeAI supports these variants and detects them on install:

VariantText encoderNotes
Klein 4BQwen3 4BDistilled for 4 steps
Klein 9BQwen3 8BDistilled for 4 steps
Klein 4B Base / Klein 9B BaseQwen3 4B / Qwen3 8BUndistilled foundation models; 28 steps
FLUX.2 [dev]Mistral Small 3.132B guidance-distilled transformer; 28 steps; non-commercial license

Every variant can take reference images for image editing (see Reference images).

Klein vs. Klein Base

A Klein model and its Base model have identical architectures, so InvokeAI tells them apart by the file or repository name: a name containing “base” (and not “distilled”) is identified as Base. If a model was identified wrongly, change its Variant in the model’s edit form in the Model Manager. It matters: Base models need 28 steps, distilled ones 4.

The Qwen3 and Mistral text encoders are Apache 2.0. The FLUX.2 [dev] ControlNet Union is released under the FLUX [dev] Non-Commercial License, like FLUX.2 [dev] itself. Some repackaged copies show a different license in their metadata; the original model’s license is the one that applies.

This is a summary, not legal advice. Read the full license on the model’s HuggingFace page before using a model commercially.

Hardware

Section titled “Hardware”

See the System Requirements table:

  • Klein 4B — 12 GB VRAM and 16 GB RAM at 1024×1024; the FP8 build works with 8 GB+. The GGUF Q4 build runs on 6–8 GB.
  • Klein 9B — 12 GB VRAM and 32 GB RAM. The int8 build is 9.5 GB on any supported GPU. The FP8 build stays that small only on an RTX 40-series (or newer) card with fp8_compute enabled; otherwise it expands to about 18 GB. The Qwen3 8B encoder is about 15 GB and streams on a 12 GB card.
  • FLUX.2 [dev] — the full Diffusers pipeline is about 80 GB. The NF4 Diffusers build runs on about 18 GB of VRAM with offloading, and the GGUF Q3_K_M transformer fits about 12 GB with offloading.

See also FP8 Storage and SDNQ quantization.

Installing

Section titled “Installing”

The FLUX.2 Klein bundle in the Model Manager is the quickest start. It installs FLUX.2 Klein 4B (GGUF Q4) together with the FLUX.2 VAE and the Qwen3 4B encoder.

A FLUX.2 model needs three components:

ComponentDiffusers installSingle-file / GGUF / FP8 / int8 install
Transformerbundledthe checkpoint itself
VAE (FLUX.2)bundledinstalled separately
Text encoderbundledKlein 4B: Qwen3 4B · Klein 9B: Qwen3 8B · [dev]: Mistral

Starter models that are not Diffusers pipelines install the VAE and the matching encoder as dependencies. Pick them in the Components section next to the model. If you have a FLUX.2 Diffusers model of the matching variant installed, InvokeAI uses its encoder and VAE automatically, so you don’t need standalone ones.

A 4B encoder only works with Klein 4B models, an 8B encoder only with Klein 9B.

When you install an FP8 checkpoint, FP8 Storage is switched on for it automatically, which keeps the file’s fp8 weights instead of expanding them.

License and access

FLUX.2 [dev] is released under a non-commercial license. Some Black Forest Labs repositories are gated on HuggingFace: if a download asks for an access token, accept the license on the model’s HuggingFace page and add your HuggingFace token under API Keys in the Model Manager.

Generation settings

Section titled “Generation settings”

Selecting a FLUX.2 model applies these defaults:

VariantStepsGuidanceSchedulerSize
Klein 4B / 9B4—Euler1024×1024
Klein 4B Base / 9B Base28—Euler1024×1024
[dev]283.5Euler1024×1024
  • Guidance — the slider next to Steps sets FLUX.2 [dev]‘s distilled guidance (0–20). It has no effect on Klein models.
  • Scheduler — Euler, Heun (2nd order; better quality at about twice the time per step) or LCM (for few steps).
  • Size — width and height must be multiples of 16.
  • Negative prompt — not available in the Generate tab or on the Canvas.

Text-to-image, image-to-image, inpainting and outpainting all work on the Canvas. FLUX.2 [dev] takes a ControlNet; Klein models take none, and FLUX.2 has no IP-Adapter support.

Reference images

Section titled “Reference images”

Every FLUX.2 model can edit or combine images from up to five reference images. Add them on the Generate tab or the Canvas and describe the result you want in the prompt. No extra model is needed.

In the workflow editor, wrap each image in a Kontext Conditioning - FLUX node and connect it (or a collection of them) to the Reference Images input of FLUX2 Denoise.

ControlNet

Section titled “ControlNet”

The FLUX.2 [dev] ControlNet Union starter model is alibaba-pai’s Fun-ControlNet-Union for FLUX.2 [dev] (~8.2 GB, FLUX [dev] Non-Commercial License). One model handles every condition: Canny, HED, Depth, Pose, MLSD, Scribble and Gray control images, plus inpainting. The starter model installs FLUX.2-dev-Fun-Controlnet-Union-2602.safetensors, the build to use: Scribble and Gray exist only in it, and the repository’s earlier file lost FLUX.2 [dev]‘s CFG distillation during control training and performs worse, which the 2602 build restores. It works with FLUX.2 [dev] only: the Klein transformers are narrower than the one it was trained beside. With a Klein model selected, a control layer’s settings and the Invoke button say that the ControlNet is not compatible, and nothing is generated until the layer is disabled or the model changed.

On the Canvas, add a Control Layer while a FLUX.2 [dev] model is selected. Its adapter type is FLUX.2 [dev] ControlNet and its pixels are the control image; the layer’s Filter turns a raster into one of the conditions (Canny, HED, Depth Anything, DW Openpose, MLSD, Scribble or Grayscale). The layer’s Weight is the model’s control scale: it ranges from 0 to 2, starts at 0.75, and 0.65 to 0.80 is the recommended range. Step range limits the steps the control applies to. Only one FLUX.2 [dev] ControlNet layer can be used per generation, and it can be combined with reference images.

When the Canvas inpaints or outpaints with a control layer present, the ControlNet also receives the image being regenerated and the mask of the region as its inpainting condition. Without a control layer, inpainting and outpainting are guided by the inpaint mask alone.

In the workflow editor, the same thing is the FLUX.2 [dev] ControlNet node feeding the Control input of FLUX2 Denoise. Give it a control Image, an Inpaint Image together with its Inpaint Mask (white is regenerated), or both. Its Control Scale, Begin Step Percent and End Step Percent are the layer’s weight and step range. The images are resized to the generation size and encoded with the VAE connected to FLUX2 Denoise; Tiled and Tile Size tile that encode, and an untiled encode that runs out of memory is retried in tiles. FLUX2 Denoise stops with a message when the ControlNet meets a Klein model.

Memory

The ControlNet’s 8.2 GB of weights stay loaded beside the [dev] transformer for the whole generation, and its blocks add activation memory that grows with the image size and the number of reference images. On a GPU that cannot hold all of it, Invoke keeps part of the models in system RAM, and each step is slower.

Regional guidance

Section titled “Regional guidance”

Regional guidance layers with a prompt are supported on the Canvas. Regional reference images are not. Regional prompts are ignored when reference images are attached; InvokeAI logs a warning when that happens.

LoRA

Section titled “LoRA”

FLUX.2 LoRAs are labelled with the variant they were trained for, and the Generate tab only offers LoRAs that match the selected model’s variant. LoRAs patch the transformer and, where they include text-encoder layers, the Qwen3 or Mistral encoder. In workflows use Apply LoRA - Flux2 Klein or Apply LoRA - FLUX.2 [dev] (and their Collection versions). Supported layouts include LyCORIS, Diffusers/PEFT and ComfyUI/OneTrainer PEFT files whose module names start with diffusion_model.. Per-layer .alpha values in these diffusion_model. files set the LoRA scale. LyCORIS LoKr and LoHA files are supported in BFL and kohya layouts; each LoKr operand may be stored whole or as a factorized _a / _b pair.

PiD super-resolution decode

Section titled “PiD super-resolution decode”

FLUX.2 Klein latents can be decoded with a PiD decoder for a 4× super-resolved image. Install PiD Decoder FLUX.2 (2K), PiD Decoder FLUX.2 (2K to 4K) or the newer PiD 1.5 Decoder FLUX.2 (2K to 4K) (also as an int8 build); see PiD Super-Resolution Decode.

FLUX2 Denoise also has a CFG Scale and a negative conditioning input, which the Generate tab leaves off (CFG 1.0).

Tiled VAE decode

Latents to Image - FLUX2 and Image to Latents - FLUX2 have Tiled and Tile Size fields. Without them, Invoke still tiles a decode that is too large for the GPU (auto_tiled_decode) or that ran out of memory, and force_tiled_decode tiles every decode and encode; see Tiled VAE decode and encode. A tiled result is not pixel-identical to an untiled one: the difference is fine, texture-level noise spread over the whole image, not seams, so the same seed does not reproduce an untiled image exactly. On a 1024×1024 FLUX.2 Klein image, a tiled decode differed from the untiled one by 5.6 of 255 per pixel value on average (about 2%), with no visible seams; at 2048×2048 by 3.3 of 255.
